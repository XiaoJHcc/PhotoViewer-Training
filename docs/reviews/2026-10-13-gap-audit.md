## 0. 结论摘要

> **用户 2026-10-13 对本审计的裁定已并入**：① **产品化底线目标 = ≥3★ 准确召回**（不是众多指标之一）；② **滑窗为第一优先机制、相似团降级为代理**；③ **不引入人类复测线**（上限即靶，标注成本用于提高模型效果）；④ **顺序信息进训练，但"末张更优"禁止规则化**。以下条目保留审计时的原始表述，裁定后的口径以 [REQUIREMENTS.md](../REQUIREMENTS.md) §3/§4 与 [METHODOLOGY.md](../METHODOLOGY.md) 为准。

1. **当前候选在产品化底线目标上贴随机线（换 AP 口径后更差：不如随机）**：test 事件 ≥3★ 召回 @12.5% 预算 = 0.139（随机 0.126，结构上限 0.525）；主判据 AP = 0.153 vs 随机 0.166（闭合 **−0.015**）。此前文档报告的 `0.1529` 是 ≥4★ 代理、且从不与随机基线并列，读数容易被误读。
2. **现行选片结构的"每相似团最多留一张"把上限压到 0.525–0.614**：test 有 **41.7%**（val 30.2%）的 ≥3★ 照片不是本团第一张，即每团贡献至多一张 ≥3★。这是结构缺陷，不是模型能力问题。
3. **相似团阈值不是 HUMAN 的窗口**：HUMAN 的机制是**时间线滑窗局部比选 + 逐层抬举**，"特征余弦 ≥0.88 连通分量"是 agent 自造代理。实测也证明 0.88 低于人类的雷同粒度：条件共晋级率在 cos 0.80–0.97 平坦、仅 ≥0.98 才下降（**幅度按 split 而异，详见 §1.2 校正注**）。
4. **主判据改为 AP 后暴露更严重的问题**（用户当日指出的漏洞，见下条 5）：**当前候选在 test 上不如随机**——AP 0.153 vs 随机 0.166，缺口闭合 **−0.015**，6 个 test 事件中 5 个低于随机。机制：`group_quality` 只给"每团代表"排名、把非代表压到底部，而 **41.7% 的 ≥3★ 照片不是本团第一张**（val 30.2%），结构上排不出来。**换掉去重结构（名次和直排）即转正**：AP 0.204、闭合 +0.046（val 0.164 / +0.051），零训练成本。
5. **验收目标本身有三处硬伤**：**12.5% 预算 + 80% 召回需排序 AUC≈0.97–0.99（近乎完全正确排序）**，且在 6/24 事件数学不可达；accuracy 目标剖面（±1≥95%）与"星级只有排序意义"相冲；旧"人类线"口径与减量不漏不是同一件事。
6. **模型差距是代际的**：留出事件内 AUC 仅 0.55–0.63（train 0.72–0.89，明显拟合训练事件）；0→1 技术闸门 AUC 0.57，是全链最弱环，而它正是 HUMAN 定义的第一期最大减量来源。
7. **文档体系的信息分层是对的，但缺三样东西**：目标仪表盘（离目标多远）、假说台账（可证伪的预测）、结论的重开条件。补上这三样，agent 才是在研究而不是在记账。

### 1.1 第一期目标指标（事件宏平均，旧星 ≥3★ 代理真值）

| **现行候选**（`group_quality`：团代表 LoRA + 团内最高 CLIP 排序） | **0.139** | 0.204 | 0.208 |
| 现行候选·简化变体（团代表 + 代表自身 CLIP 分） | 0.132 | 0.204 | 0.208 |
| LoRA 直排（无团去重） | 0.162 | 0.323 | 0.608 |
| CLIP 直排（无团去重） | 0.187 | 0.345 | 0.641 |
| **LoRA+CLIP 名次和（无团去重）** | **0.207** | 0.371 | 0.627 |

上表为 test；val 同形（现行候选 0.187 / 简化变体 0.161 / 名次和 0.210 / 结构上限 0.614 / 完美打分 0.935）。

**三条读数**：

- **贴随机线**：0.139 vs 0.126（随机）、0.139 vs 0.525（该管线结构上限）。文档过去报的"12.5% 照片召回 0.1529"是 ≥4★ 口径（同口径随机 0.124、上限 0.701），同样贴地。**换 AP 口径后连随机都不如**（0.153 vs 0.166，闭合 −0.015）——预算操纵被排除后，降序排列本身的缺陷暴露。
- **管线自锁**：现行候选在 12.5% 预算时召回 0.139，到 25%、50% 预算时只到 0.204 / 0.208——因为每个相似团只允许出一张，预算翻四倍也没有更多照片可留。**这条曲线形状本身就是管线设计失效的指纹**，此前无人在文档中指出。
- **结构上限直接封死验收**：0.525 < 0.80。即使模型完美，现行管线的"人工减量到 12.5% 且 ≥3★ 不漏 80%"也**不可能达成**（另：6/24 事件即使换成"完美打分 + 团内可选多张"也够不到 0.80，见 §1.3）。

**条件共晋级率只在 cos≥0.97–0.98 才明显塌陷**（≥3★ 由 0.11–0.13 降至 0.04–0.06，约 3 倍差距；0.88–0.97 之间平坦）。也就是说：现行的"cos≥0.88 连通分量 = 相似团、只留一张"把大量**人类明确同时保留**的照片当成了雷同。**注意这条曲线本身不给出"最优去重阈值"**——它只说明现行阈值低于人类去重粒度；阈值该定在哪、以及"团"这个代表单位是否还成立，要看选片器的实际召回（§3.1 的对照给出：不做团去重反而显著更好）。

对照 HUMAN：1★ 轮"刻意筛掉极端雷同""像素级一致则随机选"，4★ 轮"同场景横竖构图皆可且质量一致可同标 4★+"——人类自己承认的雷同粒度是"极端雷同"，不是"内容相似"。0.88 是"可比性"阈值（route-review §5 的 0.88 用于界定可比邻域），被误用成了"去重"阈值。

**推论**：`cluster_size` / `is_cluster_top` 这一整套表征（SUPERVISION §1 的"代表单位降级为团"、`m3_pair_gen.py` 的代表选取、`budget_metrics` 的每团一张）都建立在错阈值上。**"代表单位降级为团"需要重新评估**——以 0.88 连通分量定义的"团"不是人类语义里的"同机位雷同堆"。

另外，现行 `budget_metrics` 用 `is_cluster_top`/cluster_id 做"每团一张"，而 `cluster_size` 最大到 178，意味着一个 178 张的连通块只允许留 1 张——这是 §1.1 "管线自锁"的机制来源。

### 1.3 验收目标的三处硬伤

**(a) 80%@12.5% 在 6/24 事件中数学不可达。** ≥3★ 占比逐事件实测 5.3%–20.0%（HUMAN 说 3★ 约 1/8，实际 10–20% 波动）。当占比 > 12.5% 时，即使把预算全给 ≥3★，召回上限 = 12.5%/占比 < 100%。逐事件计算：

| 事件占比区间 | 数量 | 12.5% 预算下的召回上限 |
|---|---:|---|
| ≤12.5% | 12 | 100% |
| 12.5%–15.6% | 6 | 80–100% |
| >15.6% | **6** | **63–76%（80% 目标不可达）** |

**根因是把"绝对占比"的目标写成了"相对预算"的目标。** 人类选片时预算是跟着照片质量走的（HUMAN：每轮筛选留下比例"按情况浮动"），不是固定 12.5%。**用户给出的最终裁定**：改用**平均精度 AP**——它不需要预设预算，因此既不会被"多留一点"操纵，也不会随事件占比漂移（R80 二者皆犯）。

**(b) 无人类复测线。** KNOWLEDGE §3 的"人类线 0.704/0.926"是 golden 考卷（团内选优）同卷复测，**不是第一期减量指标的复测线**。~~模型 0.139 相当于人类的百分之多少、人类重做一遍能达多少，没有测过。~~ **用户 2026-10-13 裁定：不引入人类复测线**——既往已有重复盲评标注、用户见过全部照片故复测不完全可信、全库普查工作量过高；上下限（随机 / 完美打分）已足够定位目标，达标路径是逼近上限。（原文保留以存审计语境，结论已按裁定作废。）

**(c) accuracy 目标剖面与"星级只有排序意义"相冲。** REQUIREMENTS §4 保留 2026-07-19 的草案"exact ≥50% / ±1 ≥95%"。这是**在一把自身冠军位 30% 不稳、且 2★/3★ 在盲评新尺下不可分（KNOWLEDGE §1）的票数上，要求模型复现其绝对值**——按 HUMAN 自己的逻辑应当重新裁定。

### 1.4 模型能力：真实差距在哪

**事件内 AUC（按事件规模加权，test）**：

| 门槛 | 0→1 | 1→2 | 2→3 | 3→4 | 4→5 |
|---|---:|---:|---:|---:|---:|
| LoRA | 0.570 | 0.580 | 0.584 | 0.546 | 0.583 |
| 个性化 CLIP | 0.565 | 0.591 | 0.589 | 0.593 | 0.629 |
| （train 对照）LoRA | 0.722 | 0.739 | 0.736 | 0.848 | 0.893 |

- **train/留出落差 = 拟合训练事件**：LoRA 在训练事件上 0.72–0.89，到留出事件全线掉到 0.55–0.58。14 个训练事件 × 25k 张照片，模型学到的是事件内特定内容与水印式线索，不是可迁移的审美方向。
- **0→1（基本可拍性：清晰、平直、可拍）是全链最弱环，AUC 0.56–0.57**。这是 HUMAN 定义的第一期最大的减量来源（0→1 一步砍掉 40–65% 的量），也是"技术判别"本应最好做的一环——CV 网格 + 抖动 + 水平度都在库里，从没有人把它作为独立任务训练过（CV 通道此前只在"团内选优"考卷上验证过，且判为"带内增益"）。
- **注意 0★ 的复合语义**：0★ 照片里混有大量"技术合格但被近重复压低"的（HUMAN：1★ 轮刻意筛掉极端雷同；像素级一致随机选）。所以"0 vs ≥1"的 AUC 同时包含"技术判别"和"雷同取舍"两种能力，两者应拆开测（见 §3）。

## 2. 文档体系复核：制度好，缺"仪表盘 / 假说 / 重开条件"

### 2.1 结构上做对的

- L0→L1→L2 分层与"信源唯一"方向正确：HUMAN 是唯一手写真源，其余引用不复述，确实压住了此前的重复漂移。
- 认知链（需求→先验→标注→验证→结论）与用户的思路一致，比旧的"交接文档"形态好得多。

### 2.2 三个缺口

**(a) 没有目标仪表盘。** 全套文档没有一个地方能一眼回答"离目标还差多远"。STATUS 遵守"数字只留指针"，把候选数字赶到 KNOWLEDGE §5；而 KNOWLEDGE §5 只写候选自己的数字，不写随机基线与上限。结果是**读了 4 个文档也看不出 0.139 是"接近随机"还是"接近目标"**——这正是用户说"人浮于事"的制度成因：agent 报告"0.1222→0.1376 有真实收益"，而这两个数都在随机线附近，读者无法判断。

修复：STATUS 顶部增设"距目标"仪表盘（目标 / 当前 / 随机 / 上限 四列），并允许在那里写数字（打破"指针唯一"的严格性——**仪表盘的价值就是一眼可读**）。已执行。

**(b) 没有假说台账。** SUPERVISION §0.2 名为"先验登记"，实际 27 条里大部分是"裁定"与"机制确认"（星级语义、拍摄量级、范围裁定），真正的**可证伪先验**只有少数几条（#6 孤立照弱可比、#7 后期潜力、#8 审美优先级链、#11、#20、#21）。HUMAN 要的是"洞察出可能的先验信息……将理由挖掘出来"，而先验要能被证伪才有研究价值。#12（清晰度/平直度）是唯一一条写成了"先验 + 处方"形态的，它带动了 cvfuse 与水平度两条实验线——**这个形态应当被推广**。

修复：新建 [../METHODOLOGY.md](../METHODOLOGY.md) 第四节"先验→假说"，规定每条待试方向必须写成"先验（来自 HUMAN 或实测）/ 预测（可测量的数值方向）/ 最小证伪实验 / 预算"，登记后才动手。

**(c) 没有重开条件。** KNOWLEDGE §6 负知识墓碑表 25 行，绝大多数是在**同一把坏输入（display-plane-v3 之前）、同一批小样本考卷（n=9~94）、同一套指标**下判死的，且没有任何一行写明"这一条依赖哪个前提"。2026-09-26 发现训练输入自始就是错的（HEIF 平面/EXIF 方向/DPI），**在那之前判死的方向全部需要带条件复审**——例如"锐度全局选择判死""水平度全量套用判死"都是输入损坏期的结论。此外墓碑表的结论口径是"该输入/该标签/该模型/该考卷条件下无稳定增益"（09-21 收窄），但表里没有一列记录"该条件"是什么。

修复：墓碑表增设"证据强度 / 重开条件"列（L0 级弱证据 + 前提已变 = 可重开）；正在执行。

### 3.2 第一期主线：0→1 技术闸门（最高优先级的模型工作）

理由：① 减量最大（HUMAN：0→1 一步 40–65%）；② 语义最干净（清晰/平直/可拍——HUMAN 给了明确判据）；③ 现成信号最全（CV 网格 7 标量 × 32×32、抖动、水平度、等效焦距）；④ 当前 AUC 只有 0.56，离"技术判别不该这么难"的直觉差距最大。

做法建议：
- **把标签拆开**：0★ = 技术不合格 ∪ 被雷同压低。用"本段内是否存在 cos≥0.98 的更高星近重"把 0★ 分成两类，分别在两类上评估。
- **任务定义**：在**近重块内**做相对判别（本块内谁该被保留），而不是全图绝对打分——HUMAN："极相似照片不可能同时进入下一星级"。
- **特征**：全分辨率 CV 网格（现状用 518px 缩略图，这正是"人眼全分辨率显而易见、缩略图里近于不可见"的技术判别被漏掉的原因）+ DINO patch 差异 + 水平度。~~允许 EXIF 参与技术判别~~ → **用户 2026-10-13 裁定：EXIF 不必禁、当期也不入**（焦段差异最终仍回到美学评价，交给模型自行判断）；**0→1 的核心信号改为"极相似照片对中的清晰度"**——仅像素级差异的一张清晰一张抖动，答案应当明确；夜景抖动只作实例、**不得做成场景规则**（[REQUIREMENTS.md](../REQUIREMENTS.md) §5）。

### 3.3 中期：把"事件级"做成模型，而不是事后拼装

当前管线是"团代表（LoRA）+ 全局排序（CLIP）"两段拼装，两段各有各的尺度问题（route-review §5 已指出 `band_hybrid` 的分尺度问题）。更贴合 HUMAN 机制的形态是**一次前向内完成局部与全局**：

- 输入是一个**可比邻域**（段内近邻窗口 + 事件内高星代表），而不是单张照片；
- 监督直接来自 HUMAN 的锦标赛机制（段内滑窗晋级 + 高分池逐层抬举），而不是把它摊平成跨事件对；
- 输出是"在本邻域内保留哪些"的集合决策，与 3.1 的预算口径天然对齐。

这条线不要求新的标注——锦标赛标签本身就是这个机制的产物，**问题在于当前的摊平方式（pairwise win/lose）丢掉了机制里最有用的结构**（谁和谁才真被比过、逐层抬举的顺序）。

**先验落实**：HUMAN 说"邻域限制不太影响高分段的筛选"，但 KNOWLEDGE §1 实测"2★/3★ 在盲评新尺下不可分"——两者不冲突的解释是：**星级在事件内是"代表性"的排序，不是"绝对质量"的排序**（HUMAN：3★ 代表一个场景，1–3★ 雨露均沾）。若成立，则模型要学的第一件事是**局部代表性与覆盖**，而不是全局绝对美学分——这直接支持 3.3 的形态，也再次说明 4–5★ 的"绝对序"不是第一期的核心。

## 4. 方法论草案 → 已落 [../METHODOLOGY.md](../METHODOLOGY.md)

审计过程中浮现的、可长期复用的方法，已整理成草案并入 H1（详见该文档）。核心是四条：

1. **读数先放三条参照线**（随机 / 上限 / 上限即靶），缺一条不下结论；用**缺口闭合率**做跨口径可比的进度量；**主指标必须对"多留一点"免疫**（R80 不满足，AP 满足）；
2. **选片单位必须来自 HUMAN 的机制**（时间窗），不得自造代理（阈值团）；观察到的行为规律**可进特征、不可成规则**；
3. **先验必须写成可证伪的预测**，登记后才动手；
4. **结论必须带重开条件**（输入版本 / 标签版本 / 考卷版本 / 证据强度）；
5. **标注是最后手段**：先问现有标签能否回答，收益要写成对主指标的预期提升。
