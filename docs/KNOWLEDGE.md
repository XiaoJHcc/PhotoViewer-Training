## 1. 数据特征（实测）——标签与监督数据的性质

> 标签"是怎么来的"（习惯）见 [HUMAN.md](HUMAN.md) + [SUPERVISION.md](SUPERVISION.md) §0.1；本节只收**实测**出来的性质。

- **锦标赛标签的团内冠军位约三成不稳**：三批金标准盲选实测 0.732 / 0.658 / 0.667（批1/2/3，LOG 07-28 / 08-30）。与 HUMAN"多层抬举保证高分段不漏好片"不矛盾：机制保**池级不漏**（前二一致 0.926），不保**池内冠军唯一**（~30% 噪声）（2026-09-29 调和）。
- **噪声主源是人单次判断本身的时间飘忽**，不是锦标赛流程特有的腐败：原星↔盲选 0.680、盲选↔复测 0.704、原星↔复测 0.673——同协议两轮的差距与跨协议相同量级（LOG 08-31）。
- **老 2★ 与老 3★ 在盲评新尺下完全不可分**（g 曲线同塌 3.24）；硬边界只有 0→1（是否有效照片）与 4→5（是否精品）（M2 拟合，LOG 07-19；锚点以团顶为主，主要量的是段间归一化通道）。0→1 的技术语义 = 清晰（主体合焦、无抖动）+ 平直（水平≈0，建筑题材需对称/垂直线平行）+ 基本可拍性（HUMAN 09-29）。
- **老星级的跨场绝对信息弱而真实**：与盲评新尺的排序一致性 Spearman 0.290（≥3★ band 受限量程口径，LOG 07-19）。
- **绝对尺差异的构成**：事件间 14.7% / 事件内段间 34.1% / 段内张间 51.2%——段级偏移最多管约一半，另一半是每张的真实差异；段间 > 事件间，偏移必须做在段级（LOG 07-19）。
- **事件质量极差实测 ~2.1 星**：绍兴 2.41 顶、茶博 0.33 底（"好天 3★ ≠ 坏天 3★"的量级，n=9–32 小样本，LOG 07-19）。
- **配对库存结构**（v1 划分时代实测）：train window 监督 55% 是"同团双落败者"对（14197/25806，重复压低噪声最重的对占监督大头），双团顶仅 864（LOG 07-27）。
- **时间段 ≠ 一堆相似照片**：段内配对 cos 中位仅 0.42、仅 15/120 段为单团；段封顶照的段内居中度 ≥ 段中位者仅 47%（好照片常是跳出连拍团的那张，天然不居中）；相似团代表居中度 65% 天然成立——代表单位因此从"时间段"降级为"相似团"（9418 库口径，LOG 07-19）。
- **锦标赛路径依赖实测**：大段封顶约束满足率仅 0.707（首轮偶然落败者永远进不了高星）（LOG 07-19）。
- **≥3★ 占比实测**：旧库 9.8%、2025 批 14.7%、全库 12.9%；**逐事件带 5.3%–20.0%（v2 全 24 事件，2026-10-13 复算；旧述 5.3–13.9% 为更早批次口径）**（12.5% 是理想锦标赛值 50%³，实测不改产品口径——用户裁定，LOG 07-19 / 08-05 / 10-13）。
- **锦标赛晋级比例与实测金字塔互证**（HUMAN 标称 vs 全库实测，2026-09-29 复核）：HUMAN 标称 = 1★+ 减半（40–65%）/ 2★+ 约 1/4 / ≥3★ 约 1/8 / ≥4★ 约 1/16（5–10%）；实测全库 25302 组 = 1★+ 46.2% / 2★+ 25.7% / ≥3★ 12.9% / ≥4★ 5.5%——逐层命中，锦标赛结构成立。
- **增强视图对 CLS 任务无可见增量**（原片/增强/多视图三制式 47.3/47.2/46.9%，n=4622，LOG 07-19）→ 制式问题在特征解决前降级、影调对标注暂缓；**暂停项非证死**。
- **"雷同互斥"只在极相似端出现，且幅度远小于文档旧述**（同段照片对按 DINO 余弦分桶）：一张 ≥k★ 时另一张也 ≥k★ 的条件概率在 cos 0.80–0.97 全带平坦，仅 ≥0.98 桶下降——**但下降幅度按门槛与 split 而异**：≥3★ 的塌陷倍数 train 2.1×/val 1.8×/**test 仅 1.36×**，≥1★ 更是接近持平（1.03–1.27×）。**即"越像越不共晋级"方向一致，强度却不足以支撑一条硬阈值**；test 的 ≥0.98 桶只有 n=304 对，进一步削弱证据。**推论**：现行的 `cos≥0.88 连通分量 = 相似团、团内只留一张` 把"可比性"阈值误用成了"去重"阈值，属过度去重（LOG 10-13）。**注**：该曲线本身不给出"最优去重阈值"——阈值该定在哪要看选片器的实际召回（见下条与 §5），而"团"作为代表单位是否成立本身已在重评。
- **拍摄序位是真实的团内信号，但不构成美学评价**：相似团（≥3 张、唯一团顶）中团顶为"本团最后一张"的比例 0.296（test）/0.341（val）/0.289（train），而随机期望仅 0.202/0.224/0.228；为"首张"的比例只有 0.124/0.126/0.166（LOG 10-13）。序位观察不升格为评分规则；2026-10-14 对方法边界的澄清见 REQUIREMENTS §3/§4。
- **旧团每团一张的结构失效，不推出新模型必须用时间窗**：旧 cos≥0.88 团筛选造成的召回损失与结构上限见 §5。时间线是人工标签生成机制；10-13 将其推成强制选片单位的解释已由 10-14 用户澄清收窄（§7）。
- **≥3★ 占比逐事件分布 5.3%–20.0%**（24 事件）：12.5% 预算下 6/24 事件的 80% 召回目标在数学上不可达（占比 >15.6% 时上限 <80%，最低 0.63）。"12.5% 固定预算 + 80% 召回"这对判据隐含了"占比恒 <12.5%"的假设，与 HUMAN"留下比例按情况浮动"不符（LOG 10-13）。
- **"12.5% 预算 + 80% 召回"所需的排序 AUC ≈ 0.97–0.99**（二元正态换算，正例率取实测 10.8%/14.4%）：即要求模型在事件内**近乎完全正确排序**。放宽预算可迅速降到可实现区——预算 20% 需 AUC 0.92–0.93、25% 需 0.89–0.90、30% 需 0.86–0.88、50% 需 0.75。**当前实测事件内 AUC 仅 0.58**（LOG 10-13）。

## 2. 特征与迁移

- **冻结特征跨场零迁移**：线性/空间/MLP 头、ViT-S 与 ViT-L、518 与 1024、LoRA 微调——全部"能背（train≈0.98）不能带（test 贴 chance）"（探针三连 LOG 07-18/07-19；升级梯四级 LOG 07-19/07-27）。
- **泄漏 vs 事件级留出的差距是 0.99 vs 0.50**——凡不按事件级切分的评估数字全是假象（LOG 07-19）。
- **唯一可迁移的细粒度信号在相似带（cos 0.88–0.98）**：LoRA 0.586–0.588；跨内容带全模型贴 chance——这只说明内容偏好不迁移，不说明特征含可迁移的构图信息（07-27 据此判"DINO 只是内容分类器不成立"，已收窄，见 §7）；≥0.98 像素级带 0.50（技术差异 DINO 不可见，归 CV 通道）（LOG 07-27）。
- **事件级粗放置可迁移（0.71–0.76）**："这场整体比那场好"的粗判断带得走，场内细排带不走（abs 探针 LOEO，LOG 07-19）。
- **通用美学尺与个人尺几乎不相关**：CLIP-L/14+LAION 零样本 seg-rho −0.060、全 cos 带贴 chance（E4，LOG 07-27）。**注意边界**：该负结论针对零样本通用尺；当前候选使用的个性化 CLIP（同一图像嵌入 + 训练事件个人偏好拟合）是另一回事，不受此否定（LOG 09-26）。
- **监督多样性的单位是独立照片数，不是对数**：405 张盲评直督三臂全灭，318 张独立照片是瓶颈（LOG 07-28）。同理：横评三池（独立照片数 → SUPERVISION §10）派生出近 3 万对，对数不构成样本量（LOG 09-24）。

## 4. 输入链路与工程

- **渲染正路 = C# `--dump-render`**：Python 复刻渲染管线被闸门证伪（cos 0.90），训练/建库/部署必须同一像素路径（LOG 07-27）。
- **当前训练输入解码版本 = `display-plane-v3`**（2026-09-26）：修复 HEIF 容器尺寸与解码平面不一致（重复接缝/截断）、JPEG EXIF 方向未应用、DPI≠96 隐式裁切；旧 `render518` 缓存禁止与新缓存混用（LOG 09-26）。
- **输入修复对全局指标的作用在噪声带内**（LOG 10-13 复核）：同模型仅换修复输入，test 12.5% 预算照片召回 0.1222→0.1376、好代表召回 0.1762→0.1973；但**逐事件配对 bootstrap 区间跨零**（test delta +0.024，95% [−0.015, +0.060]；val delta **−0.032**，95% [−0.097, +0.010]，4 事件中 3 个为负）。旧表述"输入修复本身就是收益"收窄为：**输入修复是正确性修复（无争议），全局指标方向为正但幅度未超噪声带、且 val 上为负**；局部冠军位略回落（0.46→0.44）。
- **数据集时间窗已定型**：库内 capture_time 覆盖 2024-01-22 至 2026-05-10，之后无新增事件——后续终考只能落在**未来新拍摄**上，不存在"从库里再切"的干净终考（LOG 10-13）。
- **修复缓存与数据库存量分开**（2026-10-14 只读核验）：25,302 张修复 PNG、corrected_features.npz、LoRA/CLIP 分数指纹集合相等；NPZ 的 metadata_sha256 与现行 photos.csv 一致。DB CLS/patch 仍为 `dinov3_vits16_f32_518_v1`，CV 为不带 decode 后缀的 `cv_grid_v5_contrast`，不能假定数据库已按 display-plane-v3 重提。本轮基线只吃独立修复特征；CV/patch 重提另行验证（LOG 10-14）。
- **技术输入闸实跑通过，但旧竖图 CV/patch 不可混用**（LOG 10-14 技术核验）：按 train 事件/格式确定性抽19张，所有共享重渲染与修复 PNG 像素逐值一致，ONNX CLS 对修复特征 min cosine 0.999722（闸≥0.999）。7/19 尺寸变化，且恰为7张旧 CV 与重算不一致；其旧 patch 同位置平均 cosine 0.544–0.793，12张未变尺寸样本 CV 逐值相同。样本不支持外推全库故障率，但证实应从原片重提受影响产物，不能只改版本串。侧缓存独立落盘，旧 DB 保留。
- **DINO/CV 严格同位假设需收窄**：518输入 ViT16 的32格 patch 覆盖前512像素；CV 在完整显示朝向画面均匀采样。中心最大差5.90625输入像素，32×32形状相同并不等于中心逐像素相同。聚合CV探针不依赖此对齐，后续分块融合须明确坐标映射（`audit/out/technical_input_20261014/final_comparison/report.json` → geometry）。
