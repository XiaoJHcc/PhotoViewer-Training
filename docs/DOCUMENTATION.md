# 文档规范 Documentation Standards

> 本仓一切文档的写法、归属与维护规程。2026-09-27 文档体系重构时建立，取代旧 handover §6 与 AGENTS.md 旧"文档维护纪律"节；2026-09-29 修订：三章知识文档按**递进认知链**重新划分（需求 → 先验 → 标注 → 验证 → 结论），并立**事实唯一真源**规则（§5）。
> 文档地图（每份文档的一句话职责与阅读入口）维护在 [../AGENTS.md](../AGENTS.md)；本文档只管"怎么写、怎么改、怎么推翻"。

## 0. 认知链（三章知识文档的划分依据）

> **上游真源**：[HUMAN.md](HUMAN.md) 是用户亲笔（需求/先验/数据解读的核心部分，不可能漂移）；**一切文档与 HUMAN 冲突时以 HUMAN 为准**，他人只可引用不可改写；它由用户本人维护，不受本规范的新建/归属规程约束。
>
> **作者与可变性分层**（用户 2026-09-29 强调）：**L0 = HUMAN（初衷与数据标注的产生逻辑，永不偏移）→ L1 = 人机共确（REQUIREMENTS 的裁定记录、SUPERVISION 的先验登记与标注协议——agent 起草、用户确认）→ L2 = agent 自主（KNOWLEDGE 实测结论、EXECUTION-LOG 证据、story 叙事）**。**信源唯一**：上层已表述的内容，下层只引用、不复述——减少信源重复本身就是防冲突机制。

三章知识文档对应一条递进认知链，信息按"处于链的哪一环"归位，不允许跨环混装：

**需求（要什么）→ 先验（相信什么）→ 标注（造什么监督来验证/供给）→ 验证（怎么量、口径是什么）→ 结论（量完知道了什么）**，结论回流更新先验的验证状态、决定下一批标注。

- [REQUIREMENTS.md](REQUIREMENTS.md) 装第一环（外加数据语义裁定与原则约束）；
- [SUPERVISION.md](SUPERVISION.md) 装第二、三环（§0.1 习惯 = 历史监督的生成协议；§0.2 先验登记含验证状态；§1 起逐标注集）；
- [KNOWLEDGE.md](KNOWLEDGE.md) 装第四、五环（实测数据特征、验证口径、训练结论、负知识、可用信息总账）。

判别要点：**同一条信息可以在链上移动**（先验被实测证实后，结论入 KNOWLEDGE、先验表状态更新为"已证实"并加指针）；但任何时刻它只能有一个主归属环。

## 2. 各文档该写 / 不该写

- **STATUS.md**：该写——当前里程碑位置、当前候选与关键进展、下一步、等待用户项、已冻结参数、新会话起点；**数字级事实只留指针**（候选成绩 → KNOWLEDGE §5；资产规模 → SUPERVISION）。不该写——历史叙述、口径长考据、标注资产明细、别处已有真源的实测数字。预算 ≤80 行。
- **EXECUTION-LOG.md**：该写——每次实验的完整证据链，允许冗长，允许保留被推翻的原始表述。不该写——事后修改历史条目；纠正一律用新条目（见 §3）。
- **REQUIREMENTS.md**：该写——用户裁定过的需求、目标、成功判据、数据语义裁定、原则约束，每条带日期与来源。不该写——实验结果、当前进度、标注习惯的细节描述（→ HUMAN.md / SUPERVISION §0.1）、实测性质与数字（→ KNOWLEDGE §1）。
- **SUPERVISION.md**：该写——标注协议按实际执行情况**直接描述**（写清这条规则指的是什么、适用哪批；语义以用户裁定为准，裁定语境给出处指针即可，**不堆砌脱离语境的原话引用**）；每集必须能回答"为验证什么而标、得到了什么、中途启发了什么"；先验登记（§0.2）每条带验证状态，状态变化由 KNOWLEDGE 结论回流更新并加指针。不该写——把批次入库规则搬过来（那是 [../data/BATCHES.md](../data/BATCHES.md) 的职责：BATCHES 记"入库来源与批次特殊情况"，SUPERVISION 记"监督资产的协议与用法"）；实测结论的完整数字账（→ KNOWLEDGE，每集"得到了什么"只留定性一句话 + 指针）。
- **KNOWLEDGE.md**：该写——每条结论必须有数字与出处指针（LOG 日期条目或文件）；负知识墓碑表每行尽量一行；可用信息总账（§8）只列条目 + 状态 + 指针。不该写——没有数字支撑的观感；裸数字不带口径；未经实测的用户声明（那是先验，归 SUPERVISION §0.2）；别处已有真源的资产规模数字（→ SUPERVISION/BATCHES）。
- **analysis-story.md**：该写——改变过决策的证据、洞察→尝试→数据→结论的叙事；每章开头一句"本章回答什么问题"。不该写——当前候选数字（归 KNOWLEDGE §5）、台账四件套（配置/产物/判读/下一步）形态。正文预算 ≤500 行，超出才允许拆 `story/` 分章。

## 3. 推翻规程（结论被证伪/收窄时怎么办）

旧结论不删不改，三层各就各位：

1. **EXECUTION-LOG**：追加一条纠正条目，写明纠正了什么、证据是什么；
2. **KNOWLEDGE**：条目移入"已修正结论"区，格式 = 原表述 / 修正表述 / 纠正来源；若被推翻的是**用户先验**，同步更新 [SUPERVISION.md](SUPERVISION.md) §0.2 的验证状态与指针；
3. **story**：历史章节保留当时语境（必要时加"后于 X 收窄"半句指针），纠正后的结论在后续章节自然呈现。

禁止：改旧 LOG 条目、在旧文档里口头打补丁式覆盖、让同一结论在新旧两处各说一套。

## 4. 新建文档规程

- 阶段审查/复盘类文档一律 `docs/reviews/YYYY-MM-DD-<主题>.md`，写入即冻结（冻结后不再更新，后续纠正走 §3 进 KNOWLEDGE）。
- `docs/` 根部禁止新建无规范归属的文档；新增任何文档前先在 §1 矩阵里找到或新增它的性质归类。
- 新建/删除/移动任何文档，必须**同一笔提交**内更新 [../AGENTS.md](../AGENTS.md) 文档地图，否则任务不算完成。

## 5. 数字口径纪律

- **事实唯一真源**（用户 2026-09-29 裁定）：数字级事实只写一次——实测数字归 KNOWLEDGE，资产规模归 SUPERVISION / BATCHES，判据目标值归 REQUIREMENTS，原始证据归 LOG；其余位置一律用指针。**日期与出处标注是追溯性，不算重复**；在解读语境中允许引用数值并附指针。
- 结论性数字必须带口径与出处：考卷版本、样本量、出处条目（如"LOG 2026-08-31"）。
- 考卷/划分版本变更后，旧数字引用时必须带版本限定（如"旧考卷 0.766"），禁止裸数字跨版本比较。
- 单体 LoRA 数字按 ±6pt 种子噪声带判读（这条判读纪律本身也是知识，见 KNOWLEDGE）。

## 6. 时间型 vs 知识型判别（写东西之前先四问）

0. **它处在认知链哪一环？**（§0）需求/裁定 → REQUIREMENTS；习惯/先验/标注资产 → SUPERVISION；实测结论/验证口径 → KNOWLEDGE。一条信息只能有一个主归属环。
1. **下周还有效吗？** 是 → 知识型（REQUIREMENTS/SUPERVISION/KNOWLEDGE）；否 → 状态型（STATUS）或日志型（LOG）。
2. **是证据还是结论？** 证据（命令、数字、过程）→ LOG；结论 → KNOWLEDGE；两者都要时：LOG 记证据，KNOWLEDGE 记结论并指向 LOG。
3. **读者是人还是 agent？** 人读叙事 → story；agent 上手 → AGENTS 文档地图 + STATUS。

拿不准归属时，默认放 LOG（证据链永不嫌多），等结论稳定再沉淀到知识层。
