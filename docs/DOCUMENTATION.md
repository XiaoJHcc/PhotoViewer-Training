# 文档规范 Documentation Standards

> 本仓一切文档的写法、归属与维护规程。2026-09-27 文档体系重构时建立，取代旧 handover §6 与 AGENTS.md 旧"文档维护纪律"节。
> 文档地图（每份文档的一句话职责与阅读入口）维护在 [../AGENTS.md](../AGENTS.md)；本文档只管"怎么写、怎么改、怎么推翻"。

## 1. 分层职责矩阵

| 文档 | 性质 | 更新时机 | 内容边界 |
|---|---|---|---|
| [../AGENTS.md](../AGENTS.md) | 工程手册 | 结构/契约/入口变化时 | 怎么做：构建、目录职责、文档地图；不装知识结论 |
| [../STATUS.md](../STATUS.md) | 状态·易变 | 每会话末重写（不追加） | 现在在哪、当前候选与数字、下一步、等待用户项、冻结参数；不含历史叙述 |
| [../EXECUTION-LOG.md](../EXECUTION-LOG.md) | 日志·只增 | 每次实验追加 | 证据链底账：数据/前提/命令/结果/解读/下一步；**允许事无巨细**；历史条目不删不改 |
| [REQUIREMENTS.md](REQUIREMENTS.md) | 知识·稳定 | 用户裁定变化时 | 要什么、什么算成功；每条裁定标注日期与来源 |
| [ANNOTATIONS.md](ANNOTATIONS.md) | 知识·累积 | 新标注集或标注规则变化时 | 以标注集为主键：协议、置信度编码、规模、位置、状态、关联脚本 |
| [KNOWLEDGE.md](KNOWLEDGE.md) | 知识·累积 | 结论确立或被推翻时 | 结论 + 证据数字 + 出处指针；负知识墓碑表 |
| [analysis-story.md](analysis-story.md) | 叙事·人读 | 重大阶段节点 | 只收"改变过决策"的证据；洞察→尝试→数据→结论 |
| [reviews/](reviews/) | 冻结·带日期 | 写入后即冻结 | 阶段审查类文档唯一合法位置 |
| [../plans/](../plans/) | 计划档案 | 冻结 | 宪法（需求部分已移交 REQUIREMENTS）与契约册，历史档案 |
| [../data/](../data/) | 数据契约 | schema/批次变化时 | 库 schema 契约 + 入库批次台账（与 ANNOTATIONS 分工见 §2） |

## 2. 各文档该写 / 不该写

- **STATUS.md**：该写——当前里程碑位置、当前候选与关键数字、下一步、等待用户项、已冻结参数、新会话起点。不该写——历史叙述、口径长考据、标注资产明细（那些归 KNOWLEDGE/ANNOTATIONS，用链接指）。预算 ≤80 行。
- **EXECUTION-LOG.md**：该写——每次实验的完整证据链，允许冗长，允许保留被推翻的原始表述。不该写——事后修改历史条目；纠正一律用新条目（见 §3）。
- **REQUIREMENTS.md**：该写——用户裁定过的需求、目标、成功判据、原则约束，每条带日期与来源。不该写——实验结果、当前进度。
- **ANNOTATIONS.md**：该写——标注协议必须**原文级**（用户口径表述直接引用，不意译），每条规则带批次与出处。不该写——把批次入库规则搬过来（那是 [../data/BATCHES.md](../data/BATCHES.md) 的职责：BATCHES 记"入库来源与批次特殊情况"，ANNOTATIONS 记"监督资产的协议与用法"）。
- **KNOWLEDGE.md**：该写——每条结论必须有数字与出处指针（LOG 日期条目或文件）；负知识墓碑表每行尽量一行。不该写——没有数字支撑的观感；裸数字不带口径。
- **analysis-story.md**：该写——改变过决策的证据、洞察→尝试→数据→结论的叙事；每章开头一句"本章回答什么问题"。不该写——当前候选数字（归 STATUS/KNOWLEDGE）、台账四件套（配置/产物/判读/下一步）形态。正文预算 ≤500 行，超出才允许拆 `story/` 分章。

## 3. 推翻规程（结论被证伪/收窄时怎么办）

旧结论不删不改，三层各就各位：

1. **EXECUTION-LOG**：追加一条纠正条目，写明纠正了什么、证据是什么；
2. **KNOWLEDGE**：条目移入"已修正结论"区，格式 = 原表述 / 修正表述 / 纠正来源；
3. **story**：历史章节保留当时语境（必要时加"后于 X 收窄"半句指针），纠正后的结论在后续章节自然呈现。

禁止：改旧 LOG 条目、在旧文档里口头打补丁式覆盖、让同一结论在新旧两处各说一套。

## 4. 新建文档规程

- 阶段审查/复盘类文档一律 `docs/reviews/YYYY-MM-DD-<主题>.md`，写入即冻结（冻结后不再更新，后续纠正走 §3 进 KNOWLEDGE）。
- `docs/` 根部禁止新建无规范归属的文档；新增任何文档前先在 §1 矩阵里找到或新增它的性质归类。
- 新建/删除/移动任何文档，必须**同一笔提交**内更新 [../AGENTS.md](../AGENTS.md) 文档地图，否则任务不算完成。

## 5. 数字口径纪律

- 结论性数字必须带口径与出处：考卷版本、样本量、出处条目（如"LOG 2026-08-31"）。
- 考卷/划分版本变更后，旧数字引用时必须带版本限定（如"旧考卷 0.766"），禁止裸数字跨版本比较。
- 单体 LoRA 数字按 ±6pt 种子噪声带判读（这条判读纪律本身也是知识，见 KNOWLEDGE）。

## 6. 时间型 vs 知识型判别（写东西之前先三问）

1. **下周还有效吗？** 是 → 知识型（REQUIREMENTS/ANNOTATIONS/KNOWLEDGE）；否 → 状态型（STATUS）或日志型（LOG）。
2. **是证据还是结论？** 证据（命令、数字、过程）→ LOG；结论 → KNOWLEDGE；两者都要时：LOG 记证据，KNOWLEDGE 记结论并指向 LOG。
3. **读者是人还是 agent？** 人读叙事 → story；agent 上手 → AGENTS 文档地图 + STATUS。

拿不准归属时，默认放 LOG（证据链永不嫌多），等结论稳定再沉淀到知识层。
